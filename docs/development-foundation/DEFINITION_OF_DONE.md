# DEFINITION OF DONE — 「検証済み」の5段階（案・要レビュー）

目的: 「検証済み」「動作確認済み」の語を、**何を・どの環境で・どの証拠で**確認したかで固定する。
原則: **未実施の段階を成功扱いしない。** 実施していない段階は必ず「未実施」と書く。上位段階は下位段階を含意しない。
（`AUTODEV_RULES.md` §1「実コードを正」、PR #68 `MISSION213_CITY_LOD0.md` の「合成と実データを区別」と整合させる。）

## 5段階

| 段階 | 名称 | 何を確認したことになるか | 必須の証拠 | 不合格時の挙動 |
|---|---|---|---|---|
| V1 | 静的 | 構文・参照・設定の整合（実行しない） | 実行コマンドと出力（例 `node --check`, HTMLの参照パス存在確認, JSON.parse, `git diff --stat`）。対象ファイル一覧 | 修正して再実行。直せなければ PR を Draft のまま「V1 失敗」と記載 |
| V2 | 単体 | ロジックが**合成/fixture 入力**で期待通り | `node --test <ファイル>` の件数（tests/pass/fail/skipped）とファイル名。**skipped は成功に数えない** | fail は原因調査。flaky 疑いは再実行回数を併記。fail を残すなら理由と Issue を明記し「V2 不合格」 |
| V3 | 実データ | **実データ**（実PLATEAU/実ビルド出力等）で処理が通り、件数・範囲が妥当 | データ出典・取得日・commit/ビルドID、件数、範囲、監査スクリプトの出力。合成でないことを `fixture: real-build-output` 等で明示 | 実データ側の修正が必要か仕様確認。**合成で通っても V3 とは書かない** |
| V4 | ブラウザ | 実ブラウザ+WebGL で**描画・クリック・色・（対象の）24区**が期待通り | 使用ブラウザ/版、GPU/SwiftShader の別、URL、スクリーンショット、コンソールエラー数、取得失敗(404)数、確認した操作と結果 | 画面差分があれば不合格。SwiftShader/localhost の場合は「ソフトウェア描画・localhost」と必ず注記し、**性能値は主張しない** |
| V5 | 実機 | 実 GPU 端末・実配信URL（preview/production）で体感/性能が許容内 | 端末/OS/GPU/ブラウザ、URL とビルドID、FPS・p95・起動時間・転送量の**実測値**、日時 | 閾値未達は不合格。計測できない場合は「V5 未実施」 |

## 運用ルール
1. PR の検証欄に **V1〜V5 を全て書く**。実施していない段階は `未実施（理由）` とする。空欄・省略は不可。
2. 「成功」と書けるのは**実施した最高段階まで**。例: V2 まで実施なら「単体テスト合格。実データ・ブラウザ・実機は未実施」。
3. 合成 fixture の成功は V2（または V4 の *配線確認*）であり、V3 ではない。SwiftShader の FPS は V5 の根拠にならない。
4. `npm test` 未収録のテスト（例: `.cjs`）は、**実行したファイル名を列挙**する。「テスト全て通過」とだけ書かない。
5. ユーザー承認が必要な操作（main へのマージ、本番公開、workflow/secrets/認証変更、有料API）は検証段階とは別に承認欄で明記する。
6. 変更種別ごとの**最低要求段階**（案）:
   | 変更種別 | 最低段階 |
   |---|---|
   | 文書のみ | V1 |
   | ロジック/ツール変更 | V1 + V2 |
   | データ生成・変換 | V1 + V2 + V3 |
   | 描画・UI・クリック挙動 | V1 + V2 + V4（V3 該当時） |
   | 性能に関する主張 | V5（なければ「性能主張なし」） |

## PR 記載例

```markdown
## 検証（Definition of Done）
| 段階 | 結果 | 証拠 |
|---|---|---|
| V1 静的 | 合格 | `node --check` … / 参照パス確認 N 件 |
| V2 単体 | 合格 | `node --test tests/a.test.js tests/b.test.cjs` → tests 24 / pass 24 / fail 0 / skipped 0 |
| V3 実データ | **未実施**（ネットワーク不可の runner のため） | — |
| V4 ブラウザ | 部分: headless Chromium(SwiftShader)・localhost・合成 fixture で配線のみ確認 | screenshots/…, console error 0 |
| V5 実機 | **未実施** | FPS・転送量は未計測。性能の主張なし |

**結論**: V2 まで合格。V3〜V5 は未実施のため「検証済み」とは書かない。
**未確認点 / 残留リスク**: …
```

## 不合格の記載例
```markdown
| V2 単体 | **不合格** | tests 120 / pass 118 / fail 2（`tests/x.test.js` #7, #9）。原因調査中。マージ不可 |
```
