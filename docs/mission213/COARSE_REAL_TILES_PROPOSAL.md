# 遠景用の粗い実建物タイル(提案・未実装)

## 背景
北区 cold 転送 約33MB の主体は実LOD1(約30.7MB)/LOD2(約41.7MB ファイル群)。DSE(`?dse=1`)は斜め視(3000m/-30°, 6000m/-30°)でも
実建物寄与・フレーム時間に差がなく(下表)、再試行を打ち切る。既定OFF維持。

## 案: 実PLATEAU形状由来の粗い親タイル(輪郭保持)
- 既存 LOD1 の建物フットプリントを区/セル単位で統合(隣接建物を街区ポリゴンにマージ、高さは面積加重平均)し、押し出した低頂点数の GLB を
  3D Tiles の親タイル(geometricError 大)として生成。詳細タイルは REPLACE で子に置く。
- 200m 四角の模式LOD0ではなく実形状の輪郭を使うので格子化しない。色は既存LOD1と同一。
- クリックは詳細タイル(子)のみ。親タイルは pick 対象外。
- 影響: 追加 bytes は北区で数MB見込み(未測定)、位置は既存と同一座標系・同一gml:id非改変(親は建物IDを持たない)。
- 必要作業: `build-cloud-preview.mjs` の LOD1 生成後段に統合ステップ追加、tileset の階層化。既存LOD0置換(`citylod0swap`)との整合再検証。
- 承認ポイント: 24区全域の再生成(約10〜15分/回の runner 時間)が必要。北区のみの試作から開始し、24区展開前に承認を取る。

## 今回の判断
実装は見送り(ビルド階層化を伴い、1ジョブで安全に検証できる範囲を超えるため)。

## 追記(北区試作の結果)
- **前提の訂正**: 既存 LOD1 には粗い親タイル(`lod/g_*.glb`、REPLACE、geometricError 40)が既にある。mission79 が `coarseMinArea:0` で全棟を bbox 押し出しで残すため、北区で約 10.3MB(葉 15MB の約 65%)あり、軽くない。階層化の新設は不要。
- **試作(opt-in、既定OFF)**: `LC_COARSE_MERGE=<cellM>:<belowArea>`(例 `20:150`)。bbox 面積 < belowArea の小建物のみ、重心バケット(cellM 四方)ごとに bbox 和集合の 1 箱へ統合(高さは面積加重平均、id は `lod1c_*`=クリック対象外)。大建物は個別のまま。固定 200m 格子ではない。葉(詳細)タイル・gml:id・色・座標は不変。
- 北区実測(`--wards kita --single-pass --city-lod0`): `lod/` 10,256,792B → 6,463,712B(−37%)、親の箱数 18,130 → 11,710、頂点 362,600 → 234,200。ID 監査 OK(doubleDrawn=0、uniqueCanonicalIds 18,130 同一)。
- 同一カメラ `--compare`(swapOn、遠景10000m/3000m斜め、headless SwiftShader): 実建物寄与 0.0572→0.0572 / 0.1439→0.1443、tileFail 0、held/loaded true。合計転送 63.0MB→59.2MB(1回ずつ。ばらつき未評価)。3000m のスクリーンショットは目視で差を判別できず。
- 未検証: 親が主に選ばれる 15000m 以上や市域全体の遠景での見た目、道路/河川の塗りつぶし(統合箱の外形を画素で検証していない)、クリック、24区。
