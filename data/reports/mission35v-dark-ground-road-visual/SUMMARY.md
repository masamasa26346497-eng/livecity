## §2 地面の色

`CITY_THEME` を新設し、色の出どころを 1 か所に集めた。`name` を `'LIGHT'` に戻せば
35U までの見え方に戻る（QA 比較用に値ごと残してある）。

| | NAVY（既定） | LIGHT（戻し先） |
|---|---|---|
| 背景・fog | `0x0d1524` | `0xf6f7f3` |
| 陸 | `0x18233c` | `0xebede6` |
| 陸（データ表示） | `0x141d33` | `0xe3e5de` |
| 地表タイルの明度の振れ幅 | 0.14 | 0.05 |
| 地面からの照り返し | `0x1b2942` | `0xe8dcc8` |

方針:

- **真っ黒にしない。** 背景も陸も青成分が最大（`b > r, b > g`）。
- **陸は背景より一段明るい。** これで海岸線と市域外が明度で読める。
- **一色ベタ塗りにしない。** 既存の `tileTint()`（XY ハッシュによるタイルごとの明度差）の
  振れ幅だけを 0.05 → 0.14 に広げた。明るい地面では見えなかった差が、暗い地面では
  ごく薄いパーセル感として効く。**模様も線も plane も足していないので draw call は 1 のまま。**
- **照り返しの色を変えた。** `hemiGround` が暖色（`0xe8dcc8`）のままだと、地面がネイビーなのに
  建物の足元だけ茶色く濁る。
- CSS の `body` も同じネイビーへ。ここは 2 か所あり、後から来る Mission19 の UI block の
  `--lc-bg` が最終的に勝っていたので、そちらも合わせた（実機で `rgb(13,21,36)` を確認）。

## §3 道路（35V 時点の記録）

`COL_NAVY` パレットを追加し、暗い地面用の道路 style を別に組んだ。
**geometry は一切触っていない**（テストで `new THREE.` / `pushPolygon` / `BufferGeometry` が
暗いテーマの style 生成に現れないことを検査している）。renderClass も既存の 7 種のまま。

明るい地面のときは「道路を地表より濃く」していたが、暗い地面では **明度の向きが反転する**。

| renderClass | 暗いテーマでの作り方 |
|---|---|
| primary（車道） | `COL.road = 0xb7c0cd` そのまま＝いちばん明るい |
| bridge（高架） | 白へ 0.16 寄せて車道より少し明るく（高さの差が読める） |
| secondary（支線） | 地面色へ 0.34 寄せて一段暗く |
| pedestrian | 地面色へ 0.50 |
| sidewalk（歩道帯） | 地面色へ 0.60 |
| median（分離帯） | 緑を地面色へ 0.35 |
| faint（余白・法面） | 地面色へ 0.74＝いちばん暗い |

主道路 > 支線 > 歩道 > 余白 の順に単調に暗くなる階段になっている（テストで単調性を検査）。
歩道帯と余白が車道より一段暗いことが、そのまま **curb（縁石）の見え方** になる。

鉄道は元の紺（`0x49546a`）だと暗い地面に沈むので `0x8e9ac0` 系へ上げた。
水は明るいシアン（`0x3fb3e8`）のまま。

### やらなかったこと（正直に）

**中央線・横断歩道・交差点の白線は入れていない。** 理由は 2 つ:

- 車道・交差点・ランプは `refined-road-surface.json` の renderClass では `primary` に
  まとめられていて（index 未収録）、交差点だけを取り出せない。
- 線を引くには道路ごとに geometry が要る。618,749 棟規模のシーンで全道路に足すと
  「重くしないこと」という条件と正面からぶつかる。

今回できたのは「明度の階段」と「既存 renderClass による curb の表現」まで。
中央線・横断歩道は geometry を作る話なので、独立したミッションで扱うべき。

数が小さいほど強い:

| 主要駅 | 0.8 | 0.8 |
| 乗換駅 | 2.2 | 2.2 |

### 混み具合を実測して直した 2 点

ラベルを載せた直後の実機で数えたところ、**58 枚中 41 枚が建物名**で、駅名・地名の
居場所が無くなっていた。さらに矩形が角で触れる重なりが 58 枚中 3〜7 組残っていた。

1. **`BUILDING_LABEL_SHARE`**（far 0.15 / mid 0.30 / near 0.45）を追加。
   建物名が画面全体の上限を占められる割合に上限を掛ける。
   → 建物名 41 枚 → **26 枚**。遠景ほど絞るので §5 の「遠景では主要建物のみ」にも沿う。
2. **`RECT_MARGIN` を 0.004 → 0.0085** へ。pill の無いラベルは下地が透けるので、
   矩形がわずかに触れるだけで文字同士が被って読めない。触れる前に落とす。
   → 梅田で重なり 7 組 → **4 組**、重なり面積 0.0056 → 0.0031 NDC²。

重なりはゼロにはなっていない。残りは 33D がチラつき防止のために入れた
「再レイアウトのしきい値内ではレイアウトを維持する」挙動に由来する
（カメラが少し動く間、矩形は据え置きのまま sprite の大きさだけ更新される）。
ここを詰めるとチラつき対策と正面からぶつかるので、今回は触っていない。

### 可読性

暗い地面では、昼の「濃いインク + 白ハロー」が地面に沈む。反転の条件を
「夜かどうか」から「地図が暗いかどうか」（`darkMap = night || cityThemeDark()`）へ広げた。

- **ハロー型**（町名・区名・河川・公園・中小の建物名）→ 明るい文字 + 暗いハロー
- **pill 型**（駅・ランドマーク）→ **白い pill のまま**。ネイビーの上では白いバブルがいちばん読める
  （＝参考イメージの見た目）。暗い pill にするのは夜だけ。
- **主要ビル（mid）** → 新たに白い丸バブル。近景の細かい建物名まで白箱にすると
  画面が箱だらけになるので、near / veryNear は文字 + ハローに留めた。

テクスチャのキャッシュキーにテーマを足してある（`'d' | 'v' | 'n'`）ので、
テーマを切り替えても前のテーマの絵が再利用されない。

### QA 自体のやり直し（4 点）

最初の QA は全項目が「測れていない」状態だった。素直に書いておく:

1. `CityLabelLayer.getStats()` は存在しない（正しくは `getDebug()`）。全フィールドが `undefined` で、
   建物名 0 件という誤った結果が出ていた。
2. `readPixels` を表示済みフレームに対して呼んでいた。`preserveDrawingBuffer:false` なので
   全部 0 が返り、「地面は真っ黒」と出ていた。同じ tick で描き直してから読むよう直した。
3. `LandSurfaceLayer.getStats()` に `color` は無い。scene の material から直接読むようにした。
4. 「画面でいちばん多い色 = 地面」は近景では成り立たない。5-building-labels では建物の灰色
   `#888899` が最多になり、判定が false になっていた。「暗くて青い色が一定割合あるか」に変えた。

そして 1 件、**製品側の実バグ**も見つかった: `body` の背景を line 8 で変えても、
後から来る Mission19 の UI block の `--lc-bg:#f4f6f8` が勝っていた（実機で `rgb(244,246,248)`）。
canvas が覆うので普段は見えないが、読み込み中やリサイズの一瞬に明るい枠が出る。両方直した。

もう 1 件、35O 由来の**計測バグ**も直した: 建物名ラベルが `kind === 'building'` の分岐を
持たず、最後の `else` で **地名として数えられていた**。これでは §9-5 が測れないので
`stats.visibleBuildings` を独立させ、`getDebug()` へ出した。
