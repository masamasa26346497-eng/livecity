## 使用した写真ソース

**Wikimedia Commons のみ**（対応付けは Wikidata の P18 / P625 を使う）。

- 任意サイトのスクレイピングはしていない
- 検索結果 URL（Google 画像検索など）は使っていない
- **実行時にネットへ問い合わせない。** ビルド時に作った 1 本の JSON
  （`public/map-data/osaka-city/derived/building-photo-index.json`）を読むだけ
- ライセンスが読めない画像は索引に入れない（実測で除外 0 件＝全件ライセンスあり）

## 建物 → 写真の対応付け

### Q-id は手で固定している

名前で Wikidata を検索してそのまま採用すると別の建物に当たる。
そこで **Q-id を curation ファイルへ手で書き**、さらにビルド時に
「curation に控えた座標」と「Wikidata が返した座標」が食い違えば採用しない、という二重の確認にした。
生成スクリプトに `wbsearchentities`（名前検索）は入っていない。

### building への結び付けは「名前が一致したときだけ」

| confidence | 条件 | hover | click |
|---|---|---|---|
| **high** | 建物名が一致し、Wikidata 座標から 400m 以内 | 出す | 出す |
| medium | （廃止） | — | — |
| **unresolved** | 名前が一致しない | 出さない | 「写真は未登録です」 |

### medium（近さだけで決める）は途中で **廃止** した

最初は「名前が違っても 120m 以内に名前つき建物があれば medium」としていた。
実測したところ、その経路で選ばれた建物は **全部ちがう建物** だった:

| 期待 | 近さだけで選ばれた建物 | 距離 |
|---|---|---:|
| あべのハルカス | 新宿ごちそうビル | 75m |
| 大阪市役所 | 大阪府立中之島図書館 | 106m |
| グラングリーン大阪 | うめきたグリーンプレイス | 38m |
| 通天閣 | 新世界ニューハイツ | 42m |
| 梅田スカイビル | 日本トリム | 67m |

さらに「大阪市役所 / 大阪市中央公会堂」「なんばパークス / パークスタワー」が
**同じ canonicalId を取り合う**衝突も起きていた。
§3「推測で別建物画像を付けない」に従い、この経路ごと削除した（衝突検出は残してある）。

その結果 high は 5 件しかないが、**5 件とも正しい**。

## hover の仕様（§4）

- **dwell 380ms**。同じ建物に留まったときだけ出す（動かしている間は出さない）
- 建物が変わったら一旦消して測り直す。同じ建物なら作り直さない
- 出すのは **35Y の picking が返した canonicalId と完全一致** したときだけ（§12）
- ランドマークラベルに乗っているときは、そちらの写真を優先する
- 索引に無ければ **何も出さない**（近い建物で代用しない）
- 表示: 建物名 / サムネイル 1 枚 / 出典（Wikimedia Commons）/ ライセンス / 著者 / 「クリックで詳細」
- 位置は **左下**。右上はレイヤーパネル、右側は建物カードが占めるため
  （最初 右側に置いたら実機で隠れて見えなかった）
- 画像が読めなければ「写真を読み込めませんでした」に差し替える

## click の仕様（§5）

建物カードの中に「写真」欄を作り、hover より詳しく出す。

- 写真 1〜3 枚
- ライセンス（例: CC BY 2.5）
- 著者（例: 663highland）
- attribution 全文（著者と違うときだけ）
- 出典ページへのリンク（`rel="noopener noreferrer"`）
- Wikipedia へのリンク（あれば）
- 対応付けの根拠（例: `high（名前が一致し、Wikidata 座標から 34.3m）`）

写真が無い建物では「この建物の写真は未登録です」とだけ出す。**カード自体は壊れない。**

## attribution の方法（§10）

Commons の `extmetadata` から `LicenseShortName` / `Artist` / `Attribution` / `Credit` を取り、
索引へ保存している。`LicenseShortName` が取れない画像は索引に入れない。
hover では出典・ライセンス・著者を短縮表示、click では全文と出典ページ URL を出す。

## キャッシュ（§9）

索引は最初の 1 回だけ fetch し、以後は使い回す。直近 hover 12 件はメモリに持つ。
**hover ごとの API 呼び出しは無い**（レイヤー内の `fetch(` は 1 か所だけ）。

### QA の作り直し（隠さず書く）

1. 適当な地点を回る作りだったため、索引つき建物が画面に入らず **標本 0** になった。
   このとき `every()` が空集合で true を返し、全項目「成功」に見えた。
   → 索引の建物座標そのものへ寄せる作りへ変え、`length > 0` を必ず併記するようにした。
2. 合成クリックが効かなかった。`mousedown` は **canvas** で拾っているのに
   `window` へ投げていたため gesture が成立せず、`clickIntentAllows()` が false のままだった。
3. 画像の読み込み完了を待たずに判定していた（1.4 秒では間に合わない）。

## 未解決事項

- **hover で写真が出る建物は 5 棟だけ。** 有名建築の多く（あべのハルカス・通天閣・
  グラングリーン大阪など）は、その名前が建物データ側に存在しない
  （OSM の building に当該名称が付いていない）ため、正しく結び付けられない。
  近さで結ぶのは誤りだと実測で分かったので、**あえて出していない**。
  建物 footprint への point-in-polygon 判定（Wikidata 座標が footprint の中にあるか）を
  使えば正しく増やせるはずだが、build 時に footprint の輪郭を持っていない。次の候補。
- **`byLandmarkId` の 17 件は、まだ hover から引けていない。** ランドマークラベルの上に
  カーソルがあるときは引けるが、ランドマークが乗っている **建物** を hover しても
  出ない（建物 → ランドマークの対応が runtime に無いため）。
- 索引は 24 件の手作業。大阪市全域へ広げるには curation を増やす必要がある
  （構造は `entries` を足すだけで拡張できる）。
- `building-photo-manual.json`（§2-4 手動登録画像）は読み込みに対応済みだが、まだ空。
