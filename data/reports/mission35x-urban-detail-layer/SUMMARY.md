### 35W の結論を訂正する

35W では「OSM の crossing データがこのデータセットに無い」として横断歩道を
**交差点形状から推定**していた。これは `map-data/osaka-city/roads`（派生データ）の話で、
**PBF には crossing ノードが 32,036 件、crossing way が 53,467 件、実在していた**。
35X ではこれを実データへ置き換えたので、
**このミッションで足した要素に推定で置いたものは 1 つも無い。**
（35W の推定横断歩道は RoadDetail 側に残っているが、UrbanDetail の実データ横断歩道が
その上に重なる。RoadDetail 側の扱いは未解決事項に記載。）

### さびしさの原因（画面監査の分類）

before の 10 地点を見て分けると、足りていなかったのは
**歩道 / 街路樹 / 横断歩道 / 駐車場 / 広場 / 信号 / バス停等の小物**。
公園・河川・道路標示・建物名ラベルは 35L〜35W で既にある。

## §12 zoom 別

| band | 条件 | 出すもの |
|---|---|---|
| far | `r > 2000` | **何も出さない**（group ごと非表示） |
| mid | `800 < r ≤ 2000` | 歩道 / 駐車場 / 広場 / 分離帯 / 街路樹 |
| near | `400 < r ≤ 800` | ＋ 横断歩道 / 信号 / POI marker |
| veryNear | `r ≤ 400` | 同上（標示幅だけ実寸に近づく） |

§12 は「中景で横断歩道」としていたが、**mid（800〜2000m）では縞 1 本が 0.65px になって
見えないのに三角形だけ増える**ので、あえて near からにした（実測に基づく逸脱・報告済み）。
逆に信号は 4.6m のポールが r=800 で約 7px あり読めるので、veryNear ではなく near から出している。

## §13 パフォーマンス（13 地点の平均・実機 1440x900）

| | before（35W） | after（35X） | 差 | 目標 |
|---|---:|---:|---:|---|
| **draw call** | 150.8 | **158.6** | **+5.2%** | +20% 以内 ✓ |
| **FPS** | 51.3 | **50.1** | **−2.3%** | −10% 以内 ✓ |
| triangles | 533,488 | 677,791 | +27.0% | 指定なし |
| mesh 数 | 873.4 | 880.0 | +0.8% | — |

draw call が +8 程度で収まっているのは、

- 点もの（樹・信号・marker）は **InstancedMesh**。本数によらず種類ごとに 1 draw call
- 線・面は **見えている範囲をまとめて 1 group** に merge（タイルごとに作らない）
- カメラ注視点から `reach`（= `clamp(r × 2.4, 700, 3000)` m）の外は作らない
- 遠景は group ごと非表示

ため。実測で 1 地点あたりの UrbanDetail の draw call は **6〜10**。

### 途中で見つけて直した 2 つの実装バグ

1. **タイル取得のレース（35W にもあった）**: `ensureTile` が「取得中」を早期 return していたため、
   同じタイルを 2 回要求すると 2 回目が即解決し、まだデータの無い状態で組み立てて
   そのタイルを**永久に空として確定**していた。実機で mid band が丸ごと空になって発覚。
   取得中は同じ promise を返すよう直し、35W の RoadDetail 側も同時に修正した。
2. **タイルごとに group を作ると draw call が 36 まで増えた**（9 タイル × 4）。
   見えている範囲をまとめて 1 group にして 6〜8 へ落とした。

## 未解決事項

- **35W の推定横断歩道が RoadDetail 側に残っている。** 35X の実データ横断歩道と
  二重に描かれうる。実害は「同じ場所に 2 種類の白が重なる」程度だが、
  35W 側を実データへ寄せるか止めるかは別ミッションで決めるべき。
- **§7 公園の強化・§8 河川沿いの堤防/遊歩道は入れていない。** 公園 geometry を変形しない
  制約のもとで「walking path 風表現」を足すには park データに路線が無く、
  `embankment` 6,313 件は全国値で bbox 内の実数を測っていない。次の候補。
- **§11 の小物は 1 種類の marker にまとめている。** バス停・郵便局・警察を形で
  区別していない（色も同じ）。アイコン化は未実施。
- **三角形が +27%。** draw call と FPS は目標内だが、歩道と駐車場の塗りが効いている。
  さらに寄せるなら歩道を line ベースへ落とす余地がある。
